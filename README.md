当前版本为 **1.1.0-beta.8 测试版**。本项目是独立社区插件，与 DeepSeek Harness 官方无隶属关系。能力分类：**会话与消息**，同时包含记忆上下文、智能体角色与工作流协作。

## 功能简介

- **一个对话，一个群聊**：成员、历史、记忆和任务按宿主会话隔离。
- **自由搭配模型与角色**：每个成员独立选择已接入 API、模型、性格、职责关键词、头像和气泡颜色。
- **分类 @ 与跨群引用**：点名本群成员，或从其他群引入机器人；成员之间可以接力讨论。
- **先分工，再执行**：明确负责人、职责匹配、前置依赖、最多三名成员并行与成果汇总。
- **按成员保存记忆**：共享背景、人工固定记忆、实时观点摘录和长期摘要一起进入上下文。
- **上下级与调用权限**：只读、审批、完全访问；可选开启最高权限成员创建下级机器人。
- **可读的聊天界面**：默认不透明气泡、随机成员配色、Markdown、流式代码块、复制图标和可调整侧栏。
- **连接测试与具体错误**：显示最近连接状态，保留提供商、模型和可取得的 API 报错原因。

## 安装方式

### 懒人安装：把链接发给 DSH

复制下面这段话，发送给具备插件管理能力的 DSH 主对话：

> 请安装 https://github.com/fqxxzyw/dsh-groupchat 。先阅读 README，按当前 desktop profile 安装并启用；已有安装则升级，保留群聊数据。

普通文字 API 无法自行完成安装。安装后按 DSH 提示刷新或重启，确认群聊顶部显示 **beta.8**。

### GitHub 安装

目标为桌面端 `desktop` profile：

```bash
dsh plugin --profile desktop add github:fqxxzyw/dsh-groupchat
```

如果当前 DSH 不支持该 GitHub 来源形式，可使用下面的源码链接安装。源码链接方式已用于本项目本地测试；GitHub 来源安装仍需按你的 DSH 版本确认。

### 源码链接安装

```bash
git clone https://github.com/fqxxzyw/dsh-groupchat.git
```

把安装命令中的路径改成实际克隆目录。例如 Windows：

```bash
dsh plugin --profile desktop add link:E:/deepseek_work/dsh-groupchat
```

目录应直接包含 `package.json`、`lib/` 和 `cordis.patch.yml`。在 DSH「设置 → 插件」启用后，进入对话的「群聊」标签。

### 兼容与运行要求

- 面向 **DSH Desktop 0.2.0-rc.2**；已收到用户在 Windows 上的使用及会话切换复测正常反馈，仍需更多环境验证。
- 需要宿主提供客户端插件、`ctx.llm` 与 `ctx.webServer` 服务。包依赖声明见 [package.json](package.json)。
- 使用 DSH 已配置的 API，不需要在本插件重复填写密钥。模型请求和连接测试可能消耗提供商额度。
- 其他版本、macOS/Linux 和独立 web profile 尚未完成实际兼容验证。

## 快速上手

1. 打开一个 DSH 对话，切到 **群聊**。每个已建立的对话拥有自己的群。
2. 首次进入时选择是否导入主对话文字历史。空群会尝试继承主对话所选 API、模型和推理档位，创建「主对话助手」。
3. 点击 **成员** 添加机器人：填写名字、职责、性格、API 和模型，点 **测试连接**。
4. 输入 `@提示词专家 请帮我优化这段需求` 点名回复，或 `@所有人` 邀请本群全员。
5. 日常交流选择 **聊天**；需要交付成果时选择 **协作任务（先分工后执行）**。
6. 在 **任务** 查看负责人、依赖与成果，在 **记忆** 保存团队背景和各成员的固定要求。

没有点名的普通消息由启用成员依次回复。未知或停用成员的 @ 会提示错误并保留草稿。成员回复中的 @ 可以产生后续接力，受讨论轮数限制。

## 功能详细介绍

### 独立会话与主对话导入

群历史、任务与记忆随会话保存。草稿在当前页面运行期间按群保留。没有成员时默认使用主对话模型；暂时读不到主模型时会提示，不自动换成其他接口。

首次导入支持「询问 / 默认导入 / 默认不导入」。已有群也可点击顶部 **导入主对话**，查看可读取的记录数，刷新后追加导入。按来源事件去重，重复导入不会重复添加消息，也不会触发模型回复。

导入范围是已加载的用户和助手文字；未加载的更早历史、工具结果、思考过程不在范围内。记录数为0时，可先切到主对话等待历史加载，再返回重试。「带入主对话」则把当前文字背景和待办作为发送时的上下文，两者可以分别使用。

### 成员、头像与连接状态

每个成员可配置 API、模型、推理档位、persona、职责关键词、温度、最大输出、启用状态、颜色，以及 emoji、图片 URL 或上传头像。新建时优先随机选择本群未用颜色，创建后可手动修改。

连接测试进行一次短请求，不写入聊天历史。绿点表示最近一次连接或回复成功；红点表示失败；灰点表示未测试或停用。更改 API 或模型后，旧成功状态失效。绿点表示最近测试结果，不代表持续在线。

### 跨群引用与上下级

@ 菜单按本群成员、外群名称、机器人名字和描述分类。引入外群机器人时复制角色与模型配置到本群，名字冲突会加来源别名；历史、记忆和运行状态独立，后续配置也不会自动同步。

同一来源角色可以同时在两个群工作，停止其中一个群不会停止另一个群。父子关系用于协调优先级，禁止形成循环；任务执行仍遵守前置依赖。

| 权限 | 插件内行为 |
| --- | --- |
| 只读 | 回答、分析、完成分配的文字任务，不自动调用其他成员 |
| 审批 | 需要批准的任务或调用进入队列，等待用户通过或拒绝 |
| 完全访问 | 在上限内自动协作；本群开启机器人管理后可创建下级 |

审批等待不会阻塞其他独立任务。这里的权限管理本插件的协作行为，不授予宿主文件、终端或网络工具权限。

### 任务分工与成果交付

协作模式先生成最多六项任务，再按 **用户明确负责人 → 唯一职责关键词匹配 → 规划模型结合 persona** 分配。任务板显示负责人、状态、依赖、结果和失败原因。

互不依赖的任务最多三名成员并行，同一成员串行执行。依赖任务等待前置结果，并收到上游成果；前置失败或停止会阻止后续执行。成员可以 @ 其他成员协助，自动任务深度有上限。最后协调者汇总完成项和待办。

支持手动添加/分配任务、执行任务板、失败重试、审批与停止。当前交付包括分析、写作、提示词、代码文字和方案，不是跨机器执行程序。

### 共享记忆与个人记忆

- **共享记忆**：团队背景、目标、规范和人工固定事实。
- **成员固定记忆**：单独给某个角色的要求，按名字展示，内部按 ID 保存，改名不丢失。
- **自动记录**：成功回复后追加用户背景与成员观点摘录，每位成员保留最近八条，可关闭或清除。
- **群摘要**：点击整理记忆调用模型生成长期摘要，人工固定内容保持保留。

自动记录是未经事实核验的摘录。群数据保存在本机，每次调用时注入 API 上下文；不依赖提供商的云端对话记忆。API 提供商如何保存请求，取决于其服务政策。

### Markdown、流式输出与复制

支持标题、强调、列表、引用、表格、行内代码及代码围栏。流式代码块未闭合时也按代码显示，支持横向滚动。

消息旁和代码块右上角使用复制图标，成功后短暂显示勾号。消息复制保留原 Markdown，代码复制只取代码正文。当前为安全 Markdown 子集，原始 HTML 按文字显示，未接入语法高亮、LaTeX 和完整 CommonMark。

## 协作示例：从需求到交付

假设要设计一个“支持多角色客服的网页”，可创建以下团队：

| 成员 | 上级 | 职责关键词 | 性格设定示例 |
| --- | --- | --- | --- |
| 协调者 | 无 | 分工、汇总 | 明确目标与验收标准，优先调用已有专家，汇总实际成果与待办 |
| 提示词专家 | 协调者 | 提示词、需求、prompt | 将描述整理为输入、约束、输出与验收标准，给出可复用提示词 |
| 技能专家 | 协调者 | skill、技能、流程 | 依据提供的 skill 内容判断复用；没有合适内容则写草案，明确待验证部分 |
| 实现专家 | 协调者 | 实现、代码、架构 | 根据上游需求和流程给出架构与代码，说明假设和测试方法 |
| 评审专家 | 协调者 | 评审、检查、验收 | 检查遗漏、可用性与边界，给出改进清单 |

共享记忆可以填写：“成果使用中文，交付假设和验收建议；不要把生成代码说成已执行测试。”

选择协作任务模式，发送：

> @提示词专家 把“制作一个支持多角色客服的网页”优化为清晰需求。@技能专家 根据优化后的需求整理可复用 skill 草案。@实现专家 依赖这两份成果给出实现方案，最后请协调者汇总。

在任务板核对负责人和依赖。指定负责人优先；需要前置成果的工作会等待，不相关的工作可以并行。角色设定影响每次请求的系统提示，同一个 API 可以承载不同性格和职责，无需提供商支持专门的“云端角色”。

**工具能力边界：** 当前群成员使用普通模型接口，尚未接入联网搜索、读取本地 skill、终端或文件写入工具。可以交付 skill 草案；若要实际执行“查找 → 搜索 → 安装或创建并运行”，需由具备工具能力的主对话完成，并把真实结果导入群聊。

## 内置机器人管理协议

在群输入框开启 **允许机器人管理**，并把协调者设为 **完全访问**。例如：

> @协调者 如果现有成员没有评审职责，请创建一个下级评审机器人，继承你的模型，检查实现专家的方案并给出改进清单。

模型按内置 `groupchat-orchestrator` 协议输出管理动作，宿主验证后创建下级或调用已有成员，显示成功/失败记录。新成员继承调用者 API、模型和推理档位，以调用者为上级。

默认关闭；只读和审批角色不能自动创建。每条回复最多创建一名成员，本群已有20名成员时停止自动创建；接力受轮数/任务深度限制。该协议不会自动安装到 DSH 技能中心，也不提供外部工具权限。详细格式见 [AGENT-COLLABORATION.md](AGENT-COLLABORATION.md)。

## 全局设置

从 **设置 → 多 AI 群聊** 或顶部 **导入偏好 / 全局设置** 打开，保存后外观立即生效。

| 设置 | 默认值 | 说明 |
| --- | --- | --- |
| 历史导入 | 每次询问 | 新群首次行为；已有群仍可手动导入 |
| 气泡不透明度 | 100% | 用户和 AI 气泡统一调整，主背景保持透明 |
| 用户气泡色 | 蓝色 | 成员颜色在成员编辑中单独修改 |
| 新机器人随机颜色 | 开启 | 手动创建时优先抽取本群未用色 |
| 新群协作模式 | 关闭 | 只作为新群默认值 |
| 默认带入主对话 | 关闭 | 输入框初值，可在每个输入框单独切换 |
| Enter 发送 | 开启 | 关闭后 Enter 换行，用按钮发送；输入法确认不会发送 |
| 侧栏宽度 | 320px | 240–600px，支持拖动和方向键调整 |
| 新群允许机器人管理 | 关闭 | 已有群在输入框单独开启 |

设置保存在当前客户端，不自动跨电脑同步。恢复默认后需保存。日常设置修改无需重启；代码升级是否需要刷新/重启，以 DSH 提示及 HMR 配置为准。

## 数据、权限与问题反馈

- 群数据：`$DSH_HOME/storages/dsh-groupchat/state.json`，包含成员、文字消息、任务和记忆。未设置 DSH_HOME 时使用用户目录的 `.dsh`。
- 模型请求会把角色、相关历史、记忆和任务发送给所选 API；跨群引用不会自动传输其他群历史。
- 诊断仅记录会话标识、布局尺寸、生命周期和脱敏错误位置，不保存聊天正文或 API 密钥。没有向市场发送遥测的功能。
- 反馈时附版本、DSH 版本、系统、复现步骤及诊断文件；提交前自行检查文件中的会话标识等信息。

可点击 **导出诊断**。群聊界面未显示时，使用右下角 **群聊诊断** 或 **Ctrl+Alt+Shift+D**。自动日志在客户端运行及宿主路由可达时每约4秒保存到 `storages/dsh-groupchat/diagnostics.json`；核对文件时间与版本，避免提交旧日志。

## 开发与验证

宿主端只导入 Node 内置模块，通过宿主服务调用模型和注册 HTTP/SSE；客户端使用 DSH 模块加载器。插件配置示例：

```yaml
- id: groupchat
  name: dsh-groupchat
  config:
    maxHistoryMessages: 400
    autoDiscussionRounds: 2
    replyMaxTokens: 1024
    temperature: 1.0
    rulesAppend: ""
```

```bash
npm install
npm run check
npm test
npm run test:browser
```

浏览器测试需可用 Chromium，或设置 `GROUPCHAT_CHROMIUM_PATH`。本地自动验证使用模拟模型，不消耗真实 API。详细结果见 [TEST-RESULTS.md](TEST-RESULTS.md)，验收见 [TESTING.md](TESTING.md)。
